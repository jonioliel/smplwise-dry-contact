# SMPLwise Dry Contact

**Local digital input integration for EBYTE M31 and M31-U controllers in Home Assistant.**

<!-- repository-links:start -->
[GitHub repository](https://github.com/jonioliel/smplwise-dry-contact) · [Report an issue](https://github.com/jonioliel/smplwise-dry-contact/issues)
<!-- repository-links:end -->

אינטגרציה מקומית לבקרי EBYTE M31 ו־M31-U. הגדרת בקר לפי כתובת IP ודגם יוצרת `binary_sensor` נפרד לכל כניסה דיגיטלית, עם מצב ON/OFF ועדכון בכל שנייה כברירת מחדל. ממשק ההגדרה זמין בעברית ובאנגלית.

## דגמים נתמכים

| סדרה / דגם | כניסות מובנות | הגדרה |
|---|---|---|
| M31-U, למשל `M31-AXXXA000G-U` | לפי הדגם, 16 בדוגמה | השאר `auto`; זיהוי דגם והרחבות נתמכות |
| `M31-AXXXA000G` | 16 | בחר את הדגם ברשימה |
| `M31-AXXX8000G` | 8 | בחר את הדגם ברשימה |
| `M31-AXAX4040G` | 4 | בחר את הדגם ברשימה |
| `M31-AXAX8080G` | 8 | בחר את הדגם ברשימה |
| `M31-AAAX4440G` | 4 | בחר את הדגם ברשימה |

בסדרת M31 הרגילה, המדריך V1.1 אינו מתעד את רגיסטרי זיהוי הדגם ורשימת ההרחבות של M31-U. בחירת דגם רגיל משתמשת ברגיסטרי DI, כתובת MAC ותקינות האפיק המתועדים בשתי הסדרות. אם מחוברות הרחבות לבקר רגיל, הזן בהגדרות המתקדמות את סך כניסות ה־DI בבקר ובכל ההרחבות. אין זיהוי אוטומטי מתועד של הרחבות M31 רגיל. מצב `auto` יכול לזהות דגם רגיל רק אם הקושחה בכל זאת מספקת שם דגם מוכר ברגיסטר הזיהוי.

בדגם **M31-AXXXA000G-U** רשימת ה־IO כוללת את הכרטיס הפנימי `GAXXXA000-U` במיקום 0. האינטגרציה סופרת את הכרטיס פעם אחת ומזהה גם כרטיסי הרחבה נתמכים שמחוברים אחריו.

## התקנה דרך HACS

הוסף את [המאגר הציבורי](https://github.com/jonioliel/smplwise-dry-contact) ל־HACS:

1. פתח את **HACS** ובחר בתפריט שלוש הנקודות **Custom repositories**.
2. הוסף את כתובת מאגר GitHub ובחר סוג **Integration**.
3. חפש **SMPLwise Dry Contact**, פתח אותו ובחר **Download**.
4. הפעל מחדש את Home Assistant.
5. עבור אל **הגדרות ← מכשירים ושירותים ← הוסף אינטגרציה**, חפש **SMPLwise Dry Contact**, הזן IP ובחר את הדגם הרגיל, או `auto` עבור M31-U.

המאגר מיועד להתקנה כמאגר מותאם אישית ב־HACS. פרסום ב־GitHub אינו מוסיף אותו אוטומטית לקטלוג ברירת המחדל של HACS.

הוראות ליצירת המאגר ולפרסום גרסה: [PUBLISHING.md](PUBLISHING.md).

## התקנה ידנית

1. חלץ את קובץ ה־ZIP.
2. העתק את תיקיית `custom_components/ebyte_m31` לתיקיית ההגדרות של Home Assistant, כך שיתקבל הנתיב `/config/custom_components/ebyte_m31/manifest.json`. אם כבר קיימת תיקיית `custom_components`, הוסף את `ebyte_m31` לתוכה.
3. הפעל מחדש את Home Assistant.
4. עבור אל **הגדרות ← מכשירים ושירותים ← הוסף אינטגרציה** וחפש **SMPLwise Dry Contact**.
5. הזן את כתובת ה־IP של הבקר ובחר את הדגם: `auto` עבור M31-U או דגם M31 רגיל מהרשימה.
6. אם שינית את פורט Modbus או כתובת Modbus של הבקר, הצג את האפשרויות המתקדמות והזן אותם. ברירות המחדל הן **502** ו־**1**.

אין צורך בהגדרות YAML, ב־MQTT או בהתקנת ספריות Python נוספות. המימוש משתמש בממשקי HA של גרסאות 2025.3 ואילך; בדיקת טעינה בשרת HA אמיתי עדיין נדרשת. האייקון המקומי נתמך ב־HA מגרסה 2026.3; בגרסאות ישנות יותר ייתכן שיוצג סמל ברירת מחדל.

## הגדרות הבקר

בתוכנת ההגדרה של היצרן או בממשק האינטרנט, לפי הדגם, ודא שהרשת מוגדרת כ־**TCP Server** ושהפרוטוקול הוא **Modbus TCP**. מצב Modbus RTU over TCP אינו נתמך בחבילה זו. הבקר ושרת Home Assistant צריכים להיות מסוגלים לתקשר זה עם זה ברשת.

האינטגרציה קוראת בלבד. היא אינה משנה את כתובת הבקר, הגדרות הכניסות או יציאות הבקר. סיסמת דף האינטרנט אינה נדרשת לתקשורת Modbus.

## השימוש בכניסות

- כל כניסה מופיעה כ־**DI 1**, **DI 2**, עד מספר הכניסות הכולל, תחת מכשיר אחד.
- `on` הוא אות חשמלי פעיל בכניסה; `off` הוא אות לא פעיל. הכניסות נוצרות גם אם אין אליהן חיישן מחובר. הבקר אינו מוסר את סוג החיישן או את שמו ואינו מבדיל בהכרח בין חיישן לא פעיל לחוט מנותק.
- ניתן לשנות שם לכל ישות ב־Home Assistant, למשל ״דלת כניסה״ או ״חלון מטבח״, ולהשתמש בה באוטומציות.
- תחת **הגדר** באינטגרציה אפשר לבחור מרווח עדכון של 1–300 שניות ולהפוך כניסות ספציפיות. להיפוך כניסות 1 ו־5 הזן `1, 5` בשדה המתאים. ההיפוך משנה את התצוגה ב־HA בלבד.
- מספר כניסות **0** מפעיל זיהוי אוטומטי ב־M31-U או משתמש במספר הכניסות המובנות בדגם M31 שנבחר. אפשר לעקוף אותו עם מספר כולל מפורש של כניסות הבקר וכל ההרחבות, עד 512. ביצירה ראשונית האפשרות נמצאת בהגדרות המתקדמות.
- לאחר הוספה או הסרה של מודול הרחבה, בצע בבקר את תהליך זיהוי/תיאום המודולים המתואר במדריך, ולאחר מכן טען מחדש את האינטגרציה ב־HA. אין זיהוי של שינוי חומרה בזמן הסריקה השוטפת. ישויות ישנות של כניסות שהוסרו עשויות להישאר ברישום HA וניתן למחוק אותן לאחר הסרת המודול.
- לשינוי IP בחר בתפריט של האינטגרציה **הגדר מחדש**. מזהי הישויות נשמרים. כאשר זמינה כתובת MAC, האינטגרציה גם מאמתת שהכתובת החדשה שייכת לאותו בקר.
- בעת כשל חיבור או תקלה מדווחת באפיק ה־IO, הכניסות מסומנות **לא זמין**. חזרת התקשורת מעדכנת אותן מחדש.

זהו מנגנון סריקה. פעימות קצרות יותר ממרווח העדכון עשויות שלא להופיע; החבילה אינה כוללת מוני פעימות. בקר עם מודולי AI/DO/AO נתמכים ברשימת המודולים מציג כאן את כניסות ה־DI בלבד.

## פתרון תקלות

אם ההוספה נכשלת, בדוק גישה משרת HA לכתובת הבקר בפורט Modbus, את כתובת ה־Modbus, ואת הגדרות TCP Server / Modbus TCP. בדוק שמודולי ה־IO נמצאים במצב תקין ושבוצע תיאום כתובות לאחר שינוי חומרה. אם האינטגרציה אינה מופיעה לאחר ההעתקה, בדוק את נתיב התיקייה, הפעל מחדש את HA ורענן את הדפדפן.

דגמי M31-U המזוהים אוטומטית משתמשים בקידוד הדגם המתועד, למשל `M31-AXXXA000G-U`, `M31-AXXX8000G-U`, `M31-AXEX8080G-U` ו־`M31-AFAX4440G-U`, ובכרטיסי `G...-U` התואמים. אין תמיכה בגרסאות CAN/Profinet או בסוגי כרטיס שאינם תואמים לתבנית. כאשר טבלת המודולים אינה קיימת בקושחה, הזיהוי משתמש בכמות כניסות הבקר בלבד; במקרה כזה יש להזין ידנית כמות כוללת אם מחוברות הרחבות. בבקר רגיל ללא `-U`, בחר את הדגם בממשק במקום `auto`.

אפשר להוריד אבחון דרך תפריט האינטגרציה. הוא מכיל דגם, סדרה, קושחה (אם זמינה), רשימת מודולים ומספר כניסות, ללא כתובת IP, כתובת MAC או מצבי הכניסות.

## בסיס התיעוד

נבדק מול מדריך היצרן הסיני **M31-U 系列高性能分布式 IO 主机, V1.4**, שצורף למשימה:

| מידע | כתובת אפסית | פונקציה | סעיף במדריך |
|---|---|---|---|
| כניסות דיגיטליות | `0x0000` ואילך | `02` | 4.10.1, עמ׳ מודפס 48 |
| דגם הבקר | `0x0C20`, 12 רגיסטרים | `03` | 4.10.6, עמ׳ 60 |
| מזהה קושחה מלא | `0x0C2C`, 8 רגיסטרים | `03` | 4.10.6, עמ׳ 60 |
| טבלת כרטיסי IO | `0x0C80`, 8 רגיסטרים לכרטיס | `03` | 4.10.6, עמ׳ 61 |
| כתובת MAC | `0x7534`, 3 רגיסטרים | `03` | 4.10.7, עמ׳ 62 |
| תקלת הבקר/אפיק IO | `0x7587` | `03` | 4.10.7, עמ׳ 63 |

המדריך מסביר שהבקר כולל כרטיס הרחבה פנימי (סעיף 4.11, עמ׳ 64) ושהכתובות של כניסות מודולים נוספים ממשיכות ברצף (סעיף 4.10). ברשימת הכרטיסים נספרים כל הכרטיסים, כולל הפנימי, ללא חיבור נוסף של כניסות דגם הבקר.

מקורות ציבוריים משלימים: [עמוד הדגם הרשמי](https://www.cdebyte.com/products/M31-AXXXA000G-U/1), [מדריך אנגלי מוקדם יותר](https://www.cdebyte.com/Uploadfiles/Files/2025-5-29/2025529157331126.pdf).

התמיכה בסדרת **M31 הרגילה** מבוססת גם על **M31 Series Distributed IO Host User Manual V1.1-EN** שסופק בנפרד: דגמי DI בסעיף 1.3 (עמודים מודפסים 1–2), קריאת DI מפונקציה `02` וכתובת `0x0000` בסעיף 4.8.1 (עמ׳ 45), ו־MAC ב־`0x7534` ובדיקת תקלות ב־`0x7587` בסעיף 4.8.5 (עמ׳ 52–53). מדריך זה אינו מתעד את רגיסטרי הדגם, הקושחה ורשימת הכרטיסים `0x0C20`, `0x0C2C` ו־`0x0C80`; בחירת דגם רגיל אינה קוראת מהם.

## בדיקות ופיתוח

```text
python -m unittest discover -s tests -v
python -m compileall -q custom_components tools tests
python tools/validate_repository.py
python tools/build_release.py
```

הבדיקות מפעילות שרת Modbus TCP מדומה ומכסות זיהוי דגם והרחבות, סדר ביטים, תקלות אפיק, ניתוקים, חיבור מחדש, תשובות פגומות, timeout ותהליכי הגדרה בעזרת כפילים של ממשקי HA. הן אינן תחליף להרצת HA אמיתי או לבדיקה על החומרה. הכתובת שבצילום לא הייתה נגישה מסביבת הפיתוח ולכן לא אומתה קריאה מבקר פיזי.
